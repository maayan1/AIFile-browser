- (decision) AD paradigm (author, 2026-11-02): hexagonal / ports-and-adapters in the Python backend - all product rules (date phrases, date-only detection, ranking, Relevance Floor, Close Match, which message to show) live in the core; adapters for file system, text extraction, embedding model, index storage and UI transport. Prevents rules leaking into storage/UI code and slow, file-dependent tests. Alternatives weighed: plain layered (simpler, rules leak), pipes-and-filters everywhere (does not fit query/answer search). Future DB swap explicitly NOT a reason (C-1)
- (decision) AD transport (author, 2026-11-02): Python backend runs as a Tauri sidecar child process; UI and backend talk only over stdin/stdout, one JSON message per line, every request carries an id and every response/progress event echoes it; no localhost port. Binds all FRs, NFR-1, NFR-9, NFR-10. Prevents two incompatible channels, mismatched replies under concurrent search + indexing progress, and network-looking traffic. UI detects a dead sidecar, restarts it and shows the NFR-10 message
- (decision) AD thin UI (author, 2026-11-02): the React UI holds no product rules (no date parsing, ranking, floor, message choice); it renders what the backend returns. Prevents duplicate rule implementations in TypeScript and Python drifting apart

- (decision) AD single writer + snapshot (author, 2026-11-02): only the indexing pipeline writes the Index. Remove folder, add folder, check for new documents, rebuild and delete are commands queued to the pipeline, never direct writes. The pipeline commits in batches as a new complete version (write temp, then atomic rename); search and preview always read the latest complete version and never a partial one. Binds FR-7, FR-9..FR-11, FR-13, FR-23, NFR-8. Prevents concurrent-write corruption, resurrected entries after folder removal, and reads of half-written files. Alternative weighed: multiple writers with locks (rejected: every story must lock correctly)
- (decision) AD index storage + date fast path (author, 2026-11-02): Index lives in %LOCALAPPDATA%\FileBrowser2\index\ as manifest.json (current version number + format version) + meta-<v>.json (per-document metadata, text, Passages) + vec-<v>.npy (float32 embeddings). A commit writes the new meta/vec pair then atomically rewrites manifest.json. Backend loads the current version into memory at start and builds an in-memory list sorted by Activity Date (never persisted). Date-only search (FR-23) = range slice of that list, no model call. Date-filtered Smart Search filters by date FIRST, then scores meaning only on those Passages. Format version mismatch -> rebuild (FR-20). Binds FR-9..FR-11, FR-13..FR-17, FR-20, FR-23, NFR-2, NFR-6, NFR-8, NFR-9, C-1.
